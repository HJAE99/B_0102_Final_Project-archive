# 방화셔터 검사 rosbag 검토 GIF (2026-10-15)

robot4에서 녹화한 `shutter_1015_1043` rosbag(28.4초, Depth 284장)을 셔터 검사 코드로 재생한 결과를 GIF로 만든 자료다.
rosbag 원본(약 72MB)은 저장소에 올리지 않았고 녹화한 PC의 `~/final_ws/bags/shutter_1015_1043`에 있다.

|---|---|

맨 위 줄에는 프레임 번호, 녹화 시작 후 시간, 판정·사유(또는 평면 값과 바닥 분류 거리)를 적었다.

## 녹화 조건

- 토픽: `/robot4/oakd/rgb/image_raw/compressed`, `/robot4/oakd/stereo/image_raw/compressedDepth`, 두 CameraInfo, `tf`, `tf_static`
- 카메라 설정 변경 후: RGB·Depth 모두 704×704, 10Hz, K = 569.95 / 353.4, 354.1. RGB·Depth 촬영 시각 차이 0.08ms.
- 장면: 앞 약 10초는 빈 구역, 약 11초부터 흰 상자를 구역 안에 놓음. 로봇은 정지.

## 만든 방법

- 매니저와 같은 순서로 처리했다: 촬영 시각이 맞는 RGB·Depth 짝 → `depth_for_rgb` → TF 위쪽 방향 →
  `inspect`(구역 추적 포함, 바닥 평면은 RANSAC) → `stabilize_report`(3프레임·0.5초 확인) → `draw_result`.
- 사용한 코드는 2026-10-15 11시 무렵 작업 폴더의 `shutter_obstacle.py`·`scv_detection_manager.py`이며,
  이 커밋에는 코드 변경을 포함하지 않았다. Depth 화면 배율 보정 없음, 장애물 최소 높이 7cm다.
- 10fps 영상을 2장마다 1장(5fps, 142장), 가로 760px, 128색으로 줄였다. 실제 처리 속도를 나타내지 않는다.

## 확인 결과

- 0~10초(빈 구역): 가짜 장애물 0개, 최종 판정 `UNCONFIRMED / zone_partial`
  (구역 테두리 일부가 화면 밖이라 정상 대신 미확인).
- 약 11초(상자 놓음): 장애물 1개, `confirmation_pending`. 약 12초부터 `ABNORMAL`, 높이 약 158~160mm로 유지.
- 바닥 제거 영상에서 평면은 프레임마다 거의 같고(d 약 0.42~0.43m), 바닥 분류 거리는 약 33~44mm다.
  구역 안에 남는 가로 줄 모양 점은 이 거리를 조금 넘는 Depth 잡음이며 장애물 기준(7cm)보다 낮다.

## 바닥 제거 v2 (`shutter_1015_1043_floor_removed_v2.gif`, 2026-10-15)

같은 녹화를 아래 설정으로 다시 만든 바닥 제거 영상이다. 화면 구성은 `shutter_1015_1043_floor_removed.gif` 와 같다.

- 초점 거리 1036px (`shutter_focal_length_px`). CameraInfo 의 569.95px 는 RGB 가 1280x720 의 가운데를
  704x704 로 잘라낸 영상인데 줄인 영상 기준 값이라, 높이·거리가 약 1.8배 크게 계산됐다.
  1036px 에서 바닥 평면으로 잰 카메라 높이는 약 0.235~0.238m 로 TF 값 0.244m 와 맞는다.
- 바닥보다 아래로 잰 점(테이프·판지 이음매의 가로 무늬에서 생기는 스테레오 Depth 오차)도 지운다.
  이전 영상에서 구역 안에 남던 가로 줄 잡음은 대부분 이것이었다.
- 바닥 분류 기본 허용값 `plane_distance_m` 15mm. 판지 바닥은 기울고 가운데가 솟은 굴곡(평면 기준 약 ±10mm)이 있다.
  분류 거리는 프레임마다 약 32~38mm 다.
- 빈 구역에서 구역 안 바닥 위에 남는 픽셀은 0.000%(구역 맨 위 벽 밑단 띠 0.04% 제외)였다.
- 이 GIF 를 만든 코드 변경(초점 거리 덮어쓰기, 바닥 아래 오차 제거, 15mm)은 작업 폴더 기준이며 이 자료와 별도로 커밋한다.

## 최종 검출 (`shutter_1015_1043_final.gif`, 2026-10-15)

같은 녹화를 현재 기본값(초점 거리 1036px, 바닥 아래 Depth 오차 제거, 바닥 허용 15mm)으로 매니저와 같은 순서
(짝 → Depth 위치 맞춤 → TF 위쪽 → 구역 검출·추적 → RANSAC 바닥 → 장애물 판정 → 3프레임 확인)로 처리한 최종 결과다.
화면 구성은 왼쪽부터 RGB · 바닥을 지운 Depth(지운 바닥과 빈 Depth는 검정) · 셔터 검사 결과 화면이다.
맨 위 줄에 프레임 번호, 시간, 최종 판정·사유, 장애물 높이, 바닥 평면으로 잰 카메라 높이와 TF 카메라 높이를 적었다.

**시각적 향상을 위해** 결과 화면의 표시 방식을 바꿨다(판정 결과는 바꾸기 전과 같다).

- 예전에는 빨간 선 안의 바닥 픽셀마다 빨강을 섞어, 빈 Depth 구멍과 분류에서 빠진 점이 잡음처럼 드러났다.
- 지금은 빨간 선 안에서 물체가 아닌 곳(지운 바닥과 빈 Depth)을 반투명 보라색으로 고르게 채워 바닥임을 나타낸다.
- 바닥 위 물체만 Depth 색(0.3~4.0m, 가까울수록 파랑·멀수록 빨강)으로 덮어, 상자처럼 구역 윗변 위로 넘어간 부분까지
  물체 전체가 보이게 했다. 보라색은 Depth 색에 없는 색이라 바닥과 물체가 섞여 보이지 않는다.
- 결과 화면에 '카메라 높이 확인' 줄을 넣어 초점 거리 보정이 맞는지(바닥 평면 높이 / TF 높이 비율) 실행 중에 볼 수 있게 했다.

| 구간 | 최종 판정 (Depth 프레임 수) |
|---|---|
| 0~10.5초, 빈 구역 | `UNCONFIRMED / zone_partial` 105장, 가짜 장애물 0 |
| 10.5~12.5초, 상자 놓는 중 | 확인 중 5장, 일부 구역 7장, 경고 8장 |
| 12.5초~, 상자 | `ABNORMAL / obstacle_above_floor_inside_zone` 159장 전부 |

남은 과제: 장애물 높이는 화면상 구역 안에 들어온 상자 아랫부분만으로 재서 약 89mm(실측 185mm)로 나오고,
빈 구역은 구역 테두리 일부가 화면 밖이라 정상 대신 미확인이다. 구역(라인) 검출 단계에서 다룰 예정이다.

## 구역(라인) 검출 안정화·가림 예외처리·좌우 선 보간 검증 (2026-10-15)

`zone_stability_compare.png`, `zone_occlusion_compare.gif` 는 같은 입력을 **변경 전 코드(커밋 8ebe573)** 와
**변경 후 코드**에 똑같이 넣어 구역 선택 결과를 비교한 자료다. 기준 구역은 빈 구역 프레임의 순수 검출 다각형이다.
초점 거리 1036px 등 나머지 설정은 두 코드가 같다.

- 복원율: 기준 구역 중 결과 구역이 덮은 비율(가려진 구역을 얼마나 되찾았나)
- 정확도: 결과 구역 중 기준 안에 든 비율(구역이 얼마나 넘쳤나)

비교 장면은 다섯 가지다. 인공 가림은 실제 상자 화면 조각을 붙이고, 물체 Depth 를 아랫변 위치의 바닥 거리로 넣었다
(그 위는 바닥보다 가까운, 바닥에 서 있는 물체).

| 장면 | 복원율 (전 → 후) | 정확도 (전 → 후) | 꼭짓점 (전 → 후) |
|---|---|---|---|
| 실제 녹화 `shutter_1015_1043` (빈 구역 → 상자) | 0.989 → 0.990 | 0.960 → 0.991 | 6~11 → 6~7개 |
| 빈 구역 15장 본 뒤 물체가 오른쪽 선을 가림 | 0.964 → 0.994 | 0.996 → 0.991 | 6~10 → 7개 |
| 처음부터 큰 물체가 왼쪽 선을 가림 | 0.890 → 0.995 | 0.996 → 0.855 | 5~9 → 5~6개 |
| 처음부터 물체가 오른쪽 선을 가림 | 0.895 → 0.985 | 0.996 → 0.882 | 7~9 → 5~7개 |
| 물체 없이 왼쪽 선 일부를 지움 | 0.964 → 0.961 | 0.992 → 0.986 | 5~10 → 5~7개 |

(값은 장면별 프레임 중앙값)

- 안정화: 변경 전에는 추적 결과를 계속 우선해 옛 모양에 고정되고(실제 녹화 상자 구간 정확도 0.960 고정),
  화면 경계로 자를 때마다 꼭짓점이 늘었다. 변경 후에는 새 검출이 추적 결과와 IoU 0.95 이상 맞으면 새 검출을 쓴다.
- 가림 유지: 빈 구역을 본 뒤 물체가 선을 가리면, 이전에 보이던 테이프 픽셀이 '보임/물체에 가려짐'으로 설명될 때
  기억한 구역을 유지한다(`kept_through_occlusion`). 물체 없이 선이 사라지면 유지하지 않는다.
- 좌우 선 보간: 처음부터 물체가 한쪽 선을 가리면 기억이 없으므로, 바닥 평면 위에서 보이는 긴 선에서 띠 폭(0.80m)만큼
  떨어진 평행선을 만들어 구역을 채운다. 녹화에서 잰 좌우 선 사이 폭은 0.792m(실측 약 0.80m)다.
  남은 선의 방향이 몇 도만 어긋나도 먼 쪽에서 5~10cm 벌어져 구역이 12~15% 넘친다(정확도 0.86~0.88).
  덜 채우면 선을 가린 물체를 놓칠 수 있어, 넘침을 감수하고 복원을 우선했다.
- 물체 없이 선을 지운 장면은 선이 실제로 줄었으므로 복원율이 낮아지는 것이 맞는 동작이다.
- GIF 는 실제 녹화를 뺀 네 장면을 [변경 전 | 변경 후] 결과 화면으로 나란히 보여 준다(2.5fps, 90장).
  위 줄에 복원율·정확도·꼭짓점 수·구역 선택 방식을 적었다.
- 그래프는 위부터 복원율·정확도·꼭짓점 수다. 회색 띠는 상자를 놓는 구간 또는 가림·지움 구간이다.
