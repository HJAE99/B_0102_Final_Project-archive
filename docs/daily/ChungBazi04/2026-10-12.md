## 오늘 한 일
- 랙 상자 돌출 판별에서 테이프/상자 윤곽선이 분명하지 않으면 판정을 못 하던 원인을 확인함.
- 테이프 대신 정상 적재 상태를 기준 이미지로 저장하고, 이후 화면과 비교하는 방식으로 수정함. `n` 키로 정상 기준을 저장하며, `r` 키로 초기화하도록 구성함.
- 그레이스케일 비교 방식에서 벽과 상자의 밝기가 비슷해 검출 실패하는 문제를 확인하고, BGR 3채널 각각의 차이 중 최댓값으로 비교하는 방식(`diff.max(axis=2)`)으로 수정함. 색상 차이가 있으면 밝기가 같아도 검출됨.
- 기준 이미지를 npz 파일로 저장/로드하고, `ament_index_python`으로 소스 config 경로를 자동 탐색해 매번 경로를 지정하지 않아도 되도록 함.
- `std_srvs/srv/Trigger` 서비스 기반 랙 검사 구조로 변경함. 평소에는 검사가 꺼져 있고, 서비스 호출(`ros2 service call .../inspect_rack`)이 올 때만 활성화됨.
- `MultiThreadedExecutor` 도입 후 `cv2.imshow`가 워커 스레드에서 호출되어 GUI가 멈추는 문제를 발견하고, executor를 백그라운드 스레드에서 돌리고 메인 스레드에서 디스플레이를 처리하는 구조로 수정함.
- 1차 ROI 영역(`rack_roi_x1/y1/x2/y2` 파라미터)을 추가해 화면 전체가 아닌 랙 주변만 크롭해서 검출하도록 함. ROI는 얇은 노란 테두리로 항상 표시됨.
- 서비스 호출 시 `rack_inspect_duration`(기본 5초) 동안 검사를 유지하고 마지막 확정 판정을 반환하도록 함.
- 파라미터 튜닝: `rack_margin=30`, `rack_zone_width=90`, `rack_diff_threshold=35`로 조정해 실제 카메라에서 NORMAL/ABNORMAL 모두 정상 판정 확인함.
- 양쪽 PC(로컬·MSI) 동기화 완료. 단위 테스트 13개 전부 통과.

## 시행착오
- 그레이스케일 비교에서 벽(회색)과 상자(갈색) 밝기가 비슷해 돌출을 못 잡았음. BGR 채널별 비교로 해결함.
- `MultiThreadedExecutor`로 바꾸자 `cv2.imshow`가 워커 스레드에서 호출돼 첫 프레임 후 콜백이 멈춤(OpenCV GUI는 메인 스레드 전용). 디스플레이를 메인 스레드 루프로 분리해 해결함.
- SSH로 띄운 ROS 노드가 TurtleBot4 카메라 토픽을 발견하지 못하는 문제 발생. DDS 환경변수(`ROS_DOMAIN_ID`, `RMW_IMPLEMENTATION`)와 X디스플레이 설정이 원인이었고, MSI PC에서 직접 실행해야 정상 동작함.
- MSI PC와 로컬 PC 간 코드 동기화 시 `--symlink-install` 없이 빌드해 소스 수정이 반영 안 되는 상황 발생. 이후 반드시 `--symlink-install`로 빌드하기로 함.
