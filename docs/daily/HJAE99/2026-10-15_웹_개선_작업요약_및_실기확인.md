# 웹 정보 수신·표시 개선 작업 및 운용 PC 확인 방법

작성: 2026-10-15 · HJAE99 · 브랜치 `feature/Integration_db`

**S1 → S2 → S3 → S4 → S5 → S6 순서로 구현했다. 각 단계는 변경 범위만 확인하고 마지막에 회귀·시험 DB·가짜 ROS·브라우저를 종합 확인했다. 실제 로봇·운영 DB에서 성공했다고 기록하는 문서는 아니다.**

## 1. 달라진 동작

| 구분 | 구현 결과 |
| --- | --- |
| 시작 참고점 | HOME 숫자를 공통 JSON으로 이동. 로봇 실행기와 웹이 같은 기본값을 읽음. 기존 좌표·방향 단위·파라미터 전체 지정 우선순위 유지 |
| 지도 일치 | 픽셀 SHA-256·이미지 크기·해상도·원점 대조. 이름만 같은 다른 지도에는 시작점/구역을 그리지 않음. PostgreSQL REAL 오차는 1µm 허용 |
| 구역·Dock | zones.yaml에서 상하 구역·robot4/Z1, robot3/Z2 및 실제 Dock 위치를 읽음. DB의 기존 좌우 섹터를 ROS 구역인 것처럼 표시하지 않음 |
| 로봇 상태 | ROS 모드에서 상태·AMCL 갱신·BatteryState 구독. 수신 안 한 배터리를 100%로 표시하지 않음. 5초 이상 위치/상태 갱신이 없으면 불확실/연결 끊김으로 구분 |
| 위치 | 유효한 (0,0)은 정상 좌표. pose_ok=false의 초기 (0,0)은 표시하지 않음. 마지막 유효 위치는 회색으로 구분 |
| 통신 측정 | 기존 평균 heat 응답은 호환용 유지. 새 readings 응답은 live 중앙값과 grid_stats의 저장 중앙값·판정·신뢰도·미검출을 구분 |
| AP 선택 | 가장 센 AP를 섞지 않음. 실제 회차의 readings에 나타난 AP를 기본 선택하고 사용자가 고른 AP는 유지. DB의 등록 대상과 실제 표본을 구분 |
| 경로 | DB 작업점 또는 `/{robot}/plan`의 Nav2 계획 경로를 읽어 선택 표시. 현재 회차/일치 지도·유효 map 프레임·최신 데이터에 한함. 실제 주행 궤적으로 부르지 않음 |
| 설비·사진 | DB 등록 설비/기록을 읽고, ROS 실시간 InspectionResult도 선택 상세에 연결. 사진은 256KiB 이하·최대 20건 메모리 캐시, 선택할 때 별도 인증 GET으로 수신 |
| 메인 화면 | 지도 + 오른쪽 로봇/선택 상세 + 하단 경보. 격자·번호·시작 참고점·구역·경로 기본 숨김. ROS 모드에서는 기존 웹 순찰 명령 버튼 숨김 |
| 히트맵 | −90…−40 dBm 고정 연속 색상, 투명도·원본 칸 보기. 벽/미탐색/지도 밖 마스크. 네 칸이 모두 유효하고 충분한 표본이 있으며 사이가 전부 빈 공간일 때만 쌍선형 보간 |
| 결과·설정 | 결과는 해당 회차의 지도/같은 히트맵 도우미 사용. 완료 회차 반복 조회 중단. 상세 표/내부 관리 항목 접기. 기준 지도 파일·격자 간격을 서버 설정에서 읽어 등록 가능 |

통신 색상은 표시이고 판정을 다시 계산하지 않는다. 저장된 판정이 있으면 이를 유지한다. 보간 결과를 DB/주행/재측정 판단에 쓰지 않는다. 미검출은 점무늬, 미측정은 빈 영역이다. 표본 부족 칸은 흐리게 표시한다.

## 2. 원본과 수정 파일

- `ros2_ws/src/scv_nav/config/robot_references.json`: 기존 로봇별 undock 참고 좌표. 실제 Dock 안의 위치나 실측 현재 위치가 아님.
- `ros2_ws/src/scv_nav/scv_nav/references.py`: ROS 실행 의존성 없이 공통 기본값 읽기. mission_executor는 HOME 읽기만 변경했고 주행/초기화 규칙은 유지.
- `ros2_ws/scv_app/web_config.py`: 공통 참고 설정·지도·zones 읽기와 지도 일치 검사.
- `ros2_ws/src/scv_monitor/scv_monitor/{telemetry,ros_reader}.py`: 읽기 전용 상태/경보/결과/경로 구독. motion publisher·action/service client를 만들지 않음.
- `ros2_ws/scv_app/heatmap_data.py`, `server_page.py`: DB 통계 응답·회차 지도·ROS 텔레메트리·별도 사진 GET·기준 지도 읽기 등록.
- `ros2_ws/scv_app/static/server/{app.js,app.css,heatmap.mjs}`: 화면·레이어·통신·보간.
- `ros2_ws/scv_app/preview_web.py`: 별도 샘플 서버. 운영 앱/DB/ROS를 import하거나 실행하지 않음.
- `ros2_ws/scv_app/tests/`: 데이터, PostgreSQL API, 가짜 ROS, 히트맵 JS 및 브라우저 시나리오.

새 DB 테이블/마이그레이션은 없다. 기존 업로드·로그인·웹 agent 흐름은 유지하되 ROS 모드의 기존 agent 쓰기 차단도 유지했다. 웹 서버는 기존과 같이 worker 1개다. ROS 구독 로봇 목록은 서버 시작 시 DB 등록값을 읽으므로 로봇을 새로 등록하면 웹 서버를 재시작해야 한다.

시험용 DB 스키마는 운영 데이터와 분리했다. 테스트에서만 admin 세션 확인을 대체했으며 운영 코드의 인증은 제거하지 않았다. 라이브러리 호환성 경고 2개(httpx, pool 기본 open 정책)는 기능 실패와 별개이며, 의존성 전체 교체는 범위에 넣지 않았다.

## 4. 운용 PC 적용

관제 PC의 실제 ROS 환경과 기존 DB 연결 설정이 준비된 상태에서 다음을 사용한다. 아래 명령은 웹과 구독 연결을 띄우는 것이며 로봇 실행기/관제 주행 노드를 새로 실행하는 절차가 아니다.

```bash
cd /프로젝트/B_0102_Final_Project
source /opt/ros/jazzy/setup.bash
colcon build --base-paths ros2_ws/src --build-base ros2_ws/build --install-base ros2_ws/install --packages-select scv_nav scv_monitor --symlink-install
source ros2_ws/install/setup.bash
export SCV_RUN_OWNER=ros
# SCV_DB_DSN은 현재 관제에서 사용 중인 연결 설정을 유지한다.
# ROS_DOMAIN_ID/RMW 등은 실제 로봇과 같은 기존 운용 설정을 사용한다.
python3 ros2_ws/scv_app/server_page.py
```

로봇 PC도 변경된 scv_nav 모듈/JSON이 설치돼 있어야 mission_executor가 공통 기본값을 import할 수 있다. JSON 수정이 실행 중인 로봇의 초기 위치를 자동 변경하지 않는다. 기존 전체 x/y/yaw 지정 우선순위는 그대로다.

선택 환경 변수:

- `SCV_ROBOT_REFERENCE_CONFIG`: 공통 시작 참고 JSON 경로.
- `SCV_ZONES_CONFIG`: ROS 구역 YAML 경로.
- `SCV_REFERENCE_MAP_YAML`: 웹에서 읽어 등록할 기준 지도 YAML 경로.
- `SCV_ROBOT_MAP_PATH`: **로봇 PC에서 실제 사용하는** 지도 YAML 경로. 웹 서버 파일 경로와 다를 수 있으므로 자동 추측하지 않음. 없으면 등록 시 입력.

기존 활성 지도와 grid가 올바르면 다시 등록할 필요가 없다. 기준 지도를 새로 읽어 등록하더라도 즉시 현재 지도로 바꾸거나 기존 지도를 덮어쓰지 않는다. ROS가 쓰는 격자와 DB의 grid_size_m/셀 목록은 기존 DbStore의 일치 검사 대상이다.

## 5. 현장에서 남은 확인

- [ ] 같은 DDS 설정으로 `/robot3/status`, `/robot4/status`, AMCL, BatteryState가 웹에 실제 수신되는지.
- [ ] 실제 지도와 웹의 원점·축척·로봇 위치가 일치하는지. 다른 지도 경고가 나면 이름만 바꿔 우회하지 말고 파일/설정을 대조.
- [ ] 측정 중 readings/AP/표본 수가 DB와 일치하는지. 미검출을 강한 신호로 표시하지 않는지.
- [ ] 회차 완료/전환 후 표시 대상이 맞는지. 기준값은 DB 설정이며 ROS 실행 인자를 바꿨다면 서로 대조.
- [ ] Nav2가 실제 `/{robot}/plan`을 발행하는지. 재매핑했다면 reader 토픽도 맞출 것. 미수신 경로를 임의 직선으로 생성하지 않음.
- [ ] 상태/위치 수신 중단 후 5초 전후에 마지막 위치·연결 끊김으로 바뀌는지. AMCL이 멈췄지만 status만 오는 경우도 구분되는지.
- [ ] 실제 Alert·InspectionResult 및 축소 JPEG가 들어오는지. 사진 크기/format이 허용 조건인지.

실시간 ROS 설비 판정/사진/경보 캐시는 서버 재시작 후 보관 이력이 아니다. **ROS 설비 결과를 inspections/media/robot_events에 영구 저장하는 별도 연계는 이번 읽기 전용 표시 구현에 포함되지 않는다.** 기존 DB에 저장된 이력은 그대로 읽는다. 실시간으로 보인 사진이 결과 이력에도 영구 저장됐다고 판단하면 안 된다.

## 6. 로봇 없이 보기

`SCV_웹_미리보기.html`은 구현된 프런트를 담은 독립 파일이다. 브라우저로 열어 AP·히트맵·격자·구역·시작 참고점·로봇 상세를 조작할 수 있다. 상단의 샘플 데이터 표시를 유지한다. 그림을 새로 그린 별도 디자인 시안이 아니다.

코드에서 다시 미리보려면 웹 의존성이 설치된 Python으로 실행한다.

```bash
python3 ros2_ws/scv_app/preview_web.py
# 브라우저: http://127.0.0.1:8765/server/monitor
```

이 서버는 샘플 응답만 제공하며 로그인/제어/DB 쓰기/ROS를 실행하지 않는다. 설정 등록 기능의 동작 검증은 별도 시험 DB API 테스트에서 수행했다. 운영 연결 성공을 뜻하지 않는다.
