## 오늘 한 일
- `feature/Integration_db`에서 웹 정보 수신·표시 개선 S1~S6을 순차 진행. 공통 시작 참고값·지도/구역 조회, 읽기 전용 ROS 상태·배터리·경로 수신, DB 중앙값·판정 표시, 히트맵 색상·제한된 보간, 이력·설정 화면을 정리.
- 이후 작업 범위를 실제 코드 수정에서 **별도 UI 시안 제작**으로 전환. 기존 로봇 현황은 유지하고, 정렬된 지도에서 실시간 경로와 누적 히트맵을 보고 이력에서 원본 셀·NetSample·방문·도달 실패를 확인하는 화면을 구성.
- 부드러운 히트맵은 기본 표시로 고정하고 선택 버튼 제거. 지도는 전체 폭으로 확대하고 로봇 현황을 상단/하단에 배치한 대안과 이력 전체 표시 구성을 제작.
- 이력에 전체 표시·기본 보기와 11개 상세 레이어 개별 전환을 추가. 미측정은 회색 빈 셀, 도달 실패는 붉은 테두리·×, 회피 구역은 보라색 경계로 구분. 검은 픽셀 지도 대신 원본 기반 도면을 표시하고 축척 막대도 실제 길이 0.5m로 수정.
- 경로·시작 좌표·셀 크기는 반복 입력 대신 원본에서 읽어 표시하는 방식으로 시안에 정리. 화면별 필요한 데이터와 기존 코드의 연결 참고 위치를 인계서에 기록하고, `SCV_관제_UI_시안.html`과 인계서·사용 안내를 포함한 ZIP 전달 파일을 제작.
- 시안의 `ResizeObserver loop completed with undelivered notifications.` 오류 재현·수정. 실제 너비가 바뀔 때만 다음 화면 갱신 시점에 다시 그리고, 이전 크기 감시·대기 작업을 해제하도록 보완.

## 시행착오
- 시작 참고점·실제 로봇 위치·Dock을 같은 값으로 표시하지 않도록 구분. 미수신 배터리나 위치를 임의의 정상값으로 채우지 않도록 표시 기준을 정리.
- 미측정과 도달 실패를 비슷한 빗금으로 표시해 구분이 어려웠음. 서로 다른 면·테두리·기호를 사용하고, 상세에서는 측정 상태와 실행 실패 사유를 별도로 표시하도록 수정.
- 지도 다시 그리기가 크기 변경 알림을 반복해서 발생시킴. 이전 화면 검사에서 내부 처리된 오류를 놓친 점을 확인하고, 브라우저 오류 이벤트를 직접 수집하는 재현 검사로 보완.

## 강조하고 싶은 것 / 달성
- 웹 구현 단계 검증 기록: Python 회귀 137개, 히트맵 JS 6개, 브라우저 시나리오 22개 통과. 별도 시험 PostgreSQL·가짜 ROS 메시지 연결 및 `scv_nav`·`scv_monitor` 빌드 확인. 후속 변경은 해당 범위만 재검증.
